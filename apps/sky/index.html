LOD
How three stable drone designs share a GPU-driven level-of-detail pipeline.
← Back to 3D flights
Three designs, one stable fleet
Sci-fi drone—360 triangles full · 36 silhouette · active IDs above
Quadcopter—5,036 triangles full · 84 silhouette · active IDs above
Inspection drone—1,252 triangles full · 148 silhouette · active IDs above
Types are assigned by stable ID, independently of camera or quality. At one million: 333,334 sci-fi, 333,333 quadcopters and 333,333 inspection drones. Reference images show the original models; the runtime prepares their scale and rotors.
type = id % 3;
// The same ID keeps its design at every LOD.
How detail is selected
  1. Evaluate each active drone’s pose on the GPU.
  2. Cull against six camera planes using the shared 1.027 m swept bound.
  3. Estimate projected diameter in physical pixels.
  4. Append its stable ID to the appropriate model or marker list.
  5. Write indirect draw counts and reset counters for the next frame.
projectedPixels = (2 * radius * pixelsPerRadian) / distance;
full: enter at 13.2 px, retain to 10.8 px
silhouette: enter at 3.3 px, retain to 2.7 px
otherwise: marker
Hysteresis prevents flickering between levels. Shared caps allow at most 4,096 full models and 32,768 silhouettes. Overflow becomes markers; it does not reduce the active population.
GPU layout and resource ownership
Seven fixed indirect draws render three full designs, three silhouettes and a shared marker draw. Per-type lists select matching geometry; aggregate counters report full / silhouette / marker / visible / overflow.
Bounded full/low lists plus one population-sized marker list use a source allocation formula of 72N bytes plus bounded list overhead, small counters, arguments and route tables. This is not a new measured memory result.
Geometry/materials and compute-only buffers are explicitly released. The pinned Three 0.186.1 storage bridge remains necessary.
Source: packages/render/src/index.ts · draw-layout.ts · release-storage.ts
What is verified
Source tests check asset hashes, swept bounds, contact height, stable type counts and invalid draw-list cases. The browser audit includes all seven buckets and a 4,100-drone cap fixture.
Mixed-fleet GPU execution, resource-lifetime results and repeated close/dense/sweep timings are pending. Historical 60 FPS overview results concern the earlier renderer.

Drone Paths
How seeded routes, launch timetables and selected-drone guides are generated and evaluated.
← Back to 3D flights
The route data contract
Flight maths uses local metres, Y up and seconds. A drone descriptor is 32 bytes; a sampled route point is 48 bytes. Packed start timestamps are milliseconds and convert explicitly to seconds.
descriptor = [route, seed, phase, startMs, speed, offsetA, offsetB, flags];
// Phase, speed and offsets occupy float-bit words.
interval = min(floor(distance / spacing), sampleCount - 2);
position = mix(sample0.position, sample1.position, fraction);
Samples include position, tangent and frame data. Closed routes wrap at the seam; open routes clamp at their endpoint. CPU reference and GPU evaluation use the same packed contract.
Source: packages/core-types/src/index.ts · packages/flight/src/index.ts
London launch trips and roaming
Exactly 30% of IDs belong to scheduled ground/roof launch trips. They wait, climb, travel, land, stop and return; departures are staggered over 120 seconds. The other 70% use 120 seeded roaming groups, each with four varied 3D paths.
Timetable routes use one virtual route unit per second. Flags distinguish scheduled starts and world X/Z scatter. Supporting ground/roof contact is explicit; ordinary roaming keeps its clearance margin.
Offline swept model checks are bound to the local London source hashes. Evicting a visual tile cannot change a flight path.
Terrain estimates, authored paths and model clearance do not establish live obstacle avoidance, pad capacity or drone separation.
Source: tools/london/prepare-fleet.ts · packages/city/src/fleet.ts

Taking control of one ID
Right-click selects a drone and opens Take control. Exactly one CPU pilot state supplies an ID/pose GPU uniform override. Takeover retains current position, orientation and velocity; it coasts until the first movement input or explicit brake. Z or left-stick press brakes smoothly. The integration pass applies that override before culling, picking and collision queries. It never creates a duplicate drone.
Fixed 1/60 s simulation ticks integrate the pilot. Holding movement or turn keys ramps their target over four simulation seconds; releasing or reversing resets that direction. Damping brakes on release; blur clears all held keys and ramps.
horizontal: 12 → 32 m/s; Shift: 28 → 60 m/s
vertical:    6 → 14 m/s; Shift: 10 → 24 m/s
yaw:         1.5 → 2.4 rad/s
pitch:       0.6 → 1.2 rad/s, limited to ±45°
Escape blends the captured offset back to the moving route with a quintic transition. Body height stays below 1,200 model metres, with a conservative attitude-aware flat-ground floor (0.37 m when level). I/K pitches nose up/down; R levels it. Forward movement follows the pitched heading; strafe and independent climb remain available. Manual obstacle avoidance is not implemented.
Source: packages/flight/src/manual.ts · decision 0013
Gamepad input
The browser Gamepad API reads the paired controller once per animation frame. Standard mapping uses left-stick axes 0/1 for strafe/forward and right-stick axes 2/3 for turn/climb. A/B/X/Start are button indices 0/1/2/9; RB (5) boosts. Hold LT (6) to redirect the right vertical stick from climb to pitch; LB (4) smoothly levels it. Unmapped devices require an explicit custom profile.
A 15% rescaled dead zone rejects stick drift. Action buttons fire only on press edges. Connection changes, blur, UI focus, page navigation and audits clear input; the controller must return to neutral before rearming. Keyboard input wins any axis it actively holds, so sources do not double speed.
The same single-ID pilot handles acceleration, pause, limits and return. Device loss brakes toward hover without creating another drone or snapping to its route.
Source: packages/flight/src/gamepad.ts · apps/sky/src/gamepad-controller.ts · W3C Gamepad API
Physical Logitech/browser mapping must be verified on the connected device. Bluetooth pairing is managed by the operating system.
Camera and selection
Click picking runs only on demand. GPU passes find the nearest positive depth and resolve ties by stable ID, reading back eight bytes. Rendered buildings and nominal ground bound the pick ray.
Follow translates camera and target by the drone’s motion, preserving orbit angle and zoom. Pan map leaves Follow at the current view. Drags over five pixels do not count as clicks.
Map residency, quality and camera changes never change type assignment or active population. Page navigation changes visibility only; the running simulation remains owned by the flight viewer.
Acceptance status
Source/build and generated-shader checks are separate from actual GPU execution. CPU/GPU poses, seams, counts, picking, disposal, sustained memory and performance require their recorded browser fixtures.
Full M2 acceptance, mixed-fleet browser validation, wider devices, long soak and deployment remain pending.

Collision
How the optional GPU contact monitor works, and where its guarantees stop.
← Back to 3D flights
Capped GPU snapshots
The off-by-default monitor samples current GPU poses, at most five times per simulation second. It detects conservative rotor-sphere contacts and nearby neighbours; it does not move drones.
  1. Clear the hash-grid heads and six result counters.
  2. Insert each pose into a 4 m cell using an atomic linked list.
  3. Visit the 27 adjacent cells in 3D.
  4. Compare centre distances and count pairs once.
  5. Read back only counters.
cell = floor(position / 4); // floor matters for negative coordinates
contactDistance = 2 * 1.027; // 2.054 m
nearDistance = 4;
maxVisitsPerQuery = 256;
Source: packages/render/src/collisions.ts
Fleet and selected scopes
Whole fleet queries every active ID. Selected scope queries only the tracked ID after constructing the same grid. Negative cells, vertical offsets and hash collisions are explicitly checked; actual cell coordinates filter hash aliases.
The selected pilot override is already present in the GPU pose buffer. All three prepared designs fit the same conservative sphere.
Dense cells can exhaust the work budget. The UI reports partial/lower-bound results instead of claiming zero contacts. Diagnostics release their buffers before pose resets using the pinned storage cleanup bridge.
What the numbers mean
A rotor-sphere contact is a conservative possible contact, not mesh intersection. The near band is proximity. Snapshot checks can miss motion between samples.
This is neither continuous collision detection nor automatic avoidance. It does not test buildings or Google tile geometry. Contact counts do not prove continuous separation.
Independent CPU fixtures cover contact, proximity, negative cells, height and truncation. Browser fixtures additionally verify GPU counters and allocation lifetime; current mixed-fleet execution remains pending.

        along a sampled 3D route. Nearby drones use one of three prepared
        designs with animated rotors. Distant drones use a simplified
        silhouette or a small marker.

        Innerscene. The inspection drone is by 3DAssets.dev. All three are released under CC0.
        Their meshes are merged and rotor pivots reconstructed for this demo.
        The Credit tab links each original model.
      

      

        These are planned visual flights. Greater London uses mapped roads,
        building footprints, water and parks from OpenStreetMap. Building
        heights include estimates and ground is flat. Thirty percent depart from
        open ground or modeled roofs, travel to another site, land and return
        after a stop. Seventy percent roam in groups along varied 3D paths.
        Building clearance is checked, with intentional contact at launch
        surfaces; live avoidance, drone separation, flight dynamics and
        formation shows remain future work. Active and drawn counts are reported
